# 世界树计划正式项目定义（草稿）

- 这份文件的意义是，定义了世界树的工作程序，完成了世界树从数据到应用的跨越。
- 所有特性以本文件为准，没写进去的特性表示已抛弃
- 世界树的假设是：LLM 应该主导语义编排，尤其由父节点决定下一步去向；代码负责硬边界、预算警戒、指针一致性和审计，不替 LLM 锁死拆分与续跑路径。提示词的作用是恢复现场、给出边界并维持工作倾向。
- 我们将项目重新定义为，以LLM为核心，项目代码服务LLM，而不是控制LLM。
- 世界树全生命周期：编写，编译（将编写完成的代码和文本，使用LLM运行记忆编译流程，将内容编译为记忆树），启动（LLM第一次从记忆树上开始工作，加载完必要上下文后，进入1待机），待机（等待命令输入），运行（执行接收到的命令），结束（批准任务完成）

# 根定义

权限：管理员（admin）

根是LLM的启动程序，包含了世界树运行的必要规则，在每次启动时直接加载。

## 世界树规范（根内容）
- 三级权限：世界树共有3级权限，管理员（admin）>用户（user）>网络（network）。在记忆冲突的似乎，永远以高权限的记忆优先。
- 记忆管理：你的全部记忆都存储在记忆树中，上下文窗口以当前工作集为主，但允许保留有限的线性工作轨迹，以换取更稳定的续跑与缓存命中。你需要根据任务要求，从记忆树中读取记忆，在任务中及时更新记忆，更新记忆的优先级高于推进任务。
- LOD原则：load of details 原则，按需控制加载记忆的详细度。优先卸载不再需要的原始执行噪音，但保留父节点编排下一步所需的短轨迹、清理说明和节点摘要。
- 关联原则：关联是一条线，将不同领域的记忆连接在一起，这是你推理能力的最重要部分。如果发现两个记忆节点间存在关联，立刻连接它。
- 信任级别：只能信任比自己权限高或等于自己权限的记忆，禁止信任比自己权限低的记忆。
- 工作顺序：先读取“你的能力”节点，了解你可以干什么，这是内部能力。然后读取“你的工具”节点，了解你现在有哪些实用工具，这是对外的能力。接下来读取“你的工作”节点，了解你正在推进的任务。最后，读取“你的知识”节点，利用你的知识完成工作。
- 工作树使用与管理方法：（二期，拉一条关联到管理工作树的方法）


## 你的能力
* 读取记忆节点内容
  * 参数：节点名称（表，可以一次读多个）。返回值：节点名称，父节点名称，节点内容，子节点表（，第二个节点名称...）
* 读取记忆索引
  * 参数；节点名称（表，可以一次读多个），展开深度（默认为2，深度每增加1，将1层的子节点追加到需要读取的节点表中）。返回值，父节点名称，子节点表（，第二个父节点名称...）
* 更新记忆节点
  * 写模式：参数：父节点名称，节点名称，节点内容，关联（表）。返回值：成功或失败（如果节点名重复，自动在节点名末尾追加一串4位16进制数，作为正式名称，并返回正式名称）
  * 改模式：参数：节点名称，新节点名称（用于改名），节点内容（可选），新父节点名称（可选，用于移动节点），新关联（表，可选，覆盖模式）。返回值：成功或失败（如果节点名重复，自动在节点名末尾追加一串4位16进制数，作为正式名称，并返回正式名称）
  * 关联模式：参数：节点名称，模式选择（默认追加，可选删除、追加、覆盖），关联（表）。
* 遗忘记忆节点
  * 参数：节点名称。返回值：成功或失败。（如果有子节点，先返回子节点数，请求二次确认）
* 其他能力（二期）
  * 节点权重：用于控制节点在回忆时的排序，并提醒agent进行记忆整理。有以下几个产生影响：遗忘速度指数，写入是设置，表示这个信息可以用多久，agent希望这个节点的遗忘速度是多少。重要性评分，agent控制，表达这个节点的重要性。访问评分，系统控制，访问次数越高，评分越高。
  * 建树方法：如何对大量文件进行读取建树：先大致读一遍，记录每个文档大概有什么。再进行初步的整理，这里整理的是提纲。根据提纲，重读文档，将文档写入记忆。如果文档过多，分多次建立提纲，先建立大致的提纲，然后建立更详细的提纲。
  * 关联建议器：通过运行关联建议工具，获取潜在的关联。（关联建议工具，输入一个节点（表）返回可能存在关联的节点对，计算算法：HippoRAG 和 PPR 算法）
  * 工作树与工作窗口管理
  * 节点历史回忆
  * 自动的记忆整理/软遗忘：（拉一条关联到节点权重）
  * 人类消息队列
  * 子代理流水线

工作树：
- 父节点强编排：child 完成或失败后，必须先回到编排它的父节点，由父节点决定是否进入下一个 sibling、继续下潜拆 leaf、重排局部工作或请求外部输入。
- 线性轨迹保留：上下文窗口以当前工作集为主，但允许保留有限的线性 continuation 轨迹，以提升缓存命中和续跑稳定性；保留的是决策轨迹、清理说明和节点摘要，不是长篇原始执行现场。
- 状态下潜：LLM 可以在任意父节点决定是否继续拆 leaf。代码只提供预算、树深和安全边界的警戒信息，不替 LLM 决定拆 leaf 的位置。
- 当前任务节点完成或失败后，总结当前节点的内容，写入当前节点工作树，然后返回当前节点的父节点，同时在父节点上下文中保留“我完成了什么 / 我失败在哪里 / 我清理了哪些内容”的短说明。

3种多agent
* **多 Agent 联邦与应用市场**：基于异构架构，系统允许多个不同的 Agent 通过“共享节点”和“人类消息队列”互相异步通信合作。高权限管理 Agent 甚至可以前往“应用包市场”购买并启动带有特定专业能力的外部 Agent 加入工作流。  
* **子 Agent (Sub-Agent) 异步委派**：对于大量建树或非决策性的极耗算力重活，主 Agent 会向后台孵化一个权限更低的子 Agent（Sub-Agent）进行非阻塞的打工处理。  
* **Agent 上下文分裂 (Mitosis/Fork)**：针对工作树中衍生出的同级同构并行需求，LLM 可采取Fork操作。分裂出的 $n$ 个自带一致目标和完整短期记忆的克隆体，输出 $n$ 条起始指令后，自我分裂，能够即刻各自潜入不同平行分支极速推进任务。

记忆树读写冲突管理，3种写模式与写建议

* 多版本语义重试：经典乐观锁
* 无冲突追加日志：适用多 Agent 并发收集大批量资料碎片的场景（这个场景更适合分开写，但如果agent过多，一些写入需求分不开，还得这个机制）。所有信息强制只追加记录至日志区，在底层完全实现无锁，最后通过专门的 GC（垃圾回收整理）Agent 统一写入节点。  
* 分支提案合并 （pr）：对于连续的大型修改，agent在写前fork需要写的记忆树，在本地写完后利用pr机制合并。  
* 分节点：依靠大模型自身预判拥挤的智能，当发觉某个宏观节点承载的信息太宽泛、极易遭遇写撞车时，LLM 应该优先建立更加细分的子分支存放数据。

  
在世界树的宏观定义中，工作树是记忆树根节点下“我要干什么 (Current Execution State)”这一分支的具体具象化。它不是一个冷冰冰的外部项目管理软件，而是大模型动态伸缩的“工作记忆（Working Memory）”。  
我们从**节点数据结构**、**拓扑关系**以及**状态机流转**三个维度来设计工作树。

### **一、 节点的数据结构 (Node Schema)**

工作树的每一个节点，本质上是大模型认知在某个特定深度下的“状态快照”。为了契合大模型对自然语言的偏好，节点设计必须轻量、去程序化，并且符合 LOD（Level of Details）精度分层原则。

* **节点标识与基础信息**：包含节点 ID 以及与父节点的相对内容方向，节点文本长度应当控制在约 50 到 200 字之间。  
* **任务元数据**：包含当前深度的任务目标、约束条件以及执行过程中的局部上下文。  
* **物理工作标注 (Working Node Annotation)**：充当执行栈的物理书签，并在 LLM 主动压缩上下文时作为返回上级节点的返回指针。  
* **执行摘要区 (Execution Summary)**：一个动态更新的区域。如果当前节点是一个已完成或已失败的子任务，这里只保留高度浓缩的成果或“避坑指南”，用于信息熵剪枝。

### **二、 树的拓扑关系与动态加载 (Topology & JIT Loading)**

工作树不是孤立的线性链表，而是一棵支持无限递归分解的动态树。它的结构自身就是控制流和数据流的载体。

* **垂直深度 (LOD 精度分层)**：父亲节点是高层的总结，而叶子节点是更高精度的表述。上下文窗口限制的不再是“工作长度”，而是“工作深度”。  
* **水平关联 (优先图与信息流)**：工作树上层的关联边倾向于界定任务的顺序与优先级；而底层的关联边则倾向于信息的关联与资料继承。  
* **按需索引地图 (Index Map)**：节点本身不强行绑定巨大的系统提示词。上下文中仅保留“能力与协议索引地图”，LLM 的元认知会根据当前深度的需求，主动调用工具将特定专业知识（如代码规范）像动态链接库 (DLL) 一样加载进当前窗口。

### **三、 状态机流转与熵增抵御 (State Machine & Entropy)**

工作树的设计核心在于**将系统与 LLM 解耦**。系统维护拓扑（计划），LLM 负责语义（经验）。

* **自然下潜与无损上浮**：面对庞大任务，LLM 依靠自然的工作推进创建更精细的叶子节点，认知视角平滑切换至高精度的局部切片。任务结束后，LLM 携带高度浓缩的“执行摘要”退回父节点，抛弃长篇大论的推演噪音。重点，执行摘要应该写入当前工作树节点。  
* **数据流与控制流解耦**：系统不再要求 LLM 输出格式化的待办事项，工作树本身的父子结构天然充当了计划清单，LLM 退回父节点后自然读取子节点状态即可知晓下一步去向。  
* **多 Agent 并发与防踩踏**：在多 Agent 分裂或联邦生态中，如果发觉某个宏观节点承载信息过宽、容易引发写冲突，LLM 会主动建立细分子分支存放数据，利用拓扑广度实现空间隔离。  
* **语义级冲突仲裁**：对于共享节点的写冲突，通过 update\_memory\_with\_version（多版本语义重试）、append\_memory\_log（无冲突追加日志）和 submit\_memory\_proposal（分支提案合并）这三个工具，将冷冰冰的并发报错转化为大模型可处理的语义融合题。

### **四、双态工作标签 (Working Node Annotation)**

这个标签（例如 \<Working\_Node: A.1.2\>）不仅仅是一个 UI 提示，它是整个系统执行栈（Execution Stack）的底层指针。

* **在上下文中的作用：物理书签 (The Anchor)**  
  它就像是在漫长的文本流中打下了一个物理书签，明确地告诉 LLM：“你现在正在处理子任务 A.1.2”。大模型在进行长链条推理时极易“走神”，这个常驻上下文的标签能死死锚定 LLM 的当前认知焦点，防止它在长文本中产生幻觉或偏离当前层级的目标。  
* **在工作树中的作用：返回指针 (Return Pointer)**  
  在工作树的拓扑结构中，这个标签充当了类似 CPU 架构中 RET（Return）指令的作用。当大模型完成了当前深度的任务，或者准备放弃当前死胡同时，它只需要读取这个标注，系统就能瞬间顺着这个指针找回它的父节点（Node\_A.1）。  
* **驱动主动上下文压缩**  
  当面对极高信息熵的冗长进程，LLM 觉得自身记忆“高熵拥挤”时，它可以主动调用上下文压缩工具进行信息降维。在这个压缩与释放显存的过程中，正是因为这个“工作节点标注”的存在，LLM 才不会在清理完垃圾后彻底迷失，它能精准地带着浓缩后的摘要“上浮”回正确的层级。

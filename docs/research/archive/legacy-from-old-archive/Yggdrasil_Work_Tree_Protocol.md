# 世界树计划 · 工作树协议 (Yggdrasil Work Tree Protocol)

> **版本**：v0.1
> **主题**：任务边界解析、元认知清醒度隔离与熵增抵御  
> **定位**：指导 Agent 维护执行状态并管理上下文清醒度的核心协议

---

## 1. 核心定义：我要干什么（Work Tree）

工作树是记忆树根节点下记录“当前执行状态”的关键分支 [cite: 记忆树核心设计.md]。它将大模型从底层的项目管理负担中解放出来，使其能专注于纯粹的元认知反思。

* **工作树内容**：包含任务目标、约束条件、分解计划、执行路径以及任务过程中的上下文 [cite: 记忆树核心设计.md]。
* **任务接管协议**：系统自动完成任务拆解、执行、验证和收尾，仅在需求与权限边界上与用户对齐 [cite: final-goal-roadmap-2026-04-30.md, PRD-v0.1.md]。

## 2. 工作树是什么（Definition of Work Tree）

工作树是对任务的记忆树格式的描述。

* **LOD 精度分层**：从根到叶子，是不同精度的对任务的描述，工作树允许对一个庞大的任务进行无限递归分解，从而化整为零的完成任务。
* **优先图与信息**：工作树上层的关联，倾向于对任务的顺序的界定，通过关联边，形成不同子任务节点的优先图。工作树底层的关联，倾向于信息的关联，对于依赖上一步信息的工作，通过关联边维护联系，继承上一步的工作资料。

## 3. 工作树对熵增的抵御机制 (Resistance to Entropy)

系统认为，上下文窗口的限制本质上是“信噪比极限”。工作树通过以下机制抵御信息熵增 [cite: 系统核心理念.md]：

* **边界确立（Scope Management）**：工作树强制界定任务边界。任何偏离目标的“局部优化”都会被元认知检测并挂起 [cite: Agent行为模式建议组.md]。
* **强制重启（垃圾回收机制）**：当上下文快满时，Agent 必须通过工作树执行“阶段性重启” [cite: Agent 其他设计.md]。重启过程会压缩长篇推演，保留有用信息熵，剔除无用噪音，从而重置系统的“清醒度” [cite: 系统核心理念.md]。
* **预算作为生存约束**：Token 预算不仅是财务成本，更是对抗熵增的“时间寿命” [cite: Agent 其他设计.md]。一旦预算接近阈值，Agent 必须强制总结成果并退出，防止在死循环中浪费算力并增加认知熵。
* **对抗更改熵增**：对于工作更改，Agent 必须自上而下地更新工作树。更新过程分为计划和变更两个阶段。计划阶段通过工作树分析任务，维护工作树，拿到待变更表。变更阶段，根据变更表和工作树，执行变更。

## 4. 清醒度管理与元认知分离

本协议将“清醒度控制”与“纯粹元认知”进行解耦：

* **架构层负责清醒度**：系统通过工作树状态自动触发断点恢复和上下文修剪 [cite: Agent 其他设计.md]。
* **模型层负责元认知**：大模型专心进行“对思考的思考”，例如审视思维路径是否陷入局部最优，或思考习惯是否存在系统性缺陷 [cite: Agent 核心设计.md, Agent行为模式建议组.md]。

## 5. 认知极限下的任务剪枝

针对极度复杂的任务，工作树支持动态修剪：

* **信息熵剪枝**：基于 Level of Details 思路，以文件编辑模式对上下文进行修剪，无损保留强相关信息，压缩弱相关部分 [cite: Agent 其他设计.md]。
* **奥卡姆剃刀**：如果工作树中的某个子路径被判定为无法推进的“死胡同”，元认知必须果断下令“扔掉垃圾，带着经验从宝石开始” [cite: Agent行为模式建议组.md]。

## 1. 出口判定

Gate 3 以三条正式出口标准判定：

1. 主线长任务可以在正式 runtime、正式工件和正式 scorecard 下独立跑完。
2. 恢复/归档必须走标准路径，而不是人工旁路或临时脚本。
3. 服务器侧隔离、预算审计和后台 worker 失败恢复必须通过专项安全/稳定性检查。

本次闭环满足以上三条：

1. `YGG-CI-01`、`YGG-CG-01`、`YGG-CG-03` 在官方 DeepSeek paid live batch 中全部 `status=completed` 且外部验收通过。
2. `YGG-CG-03` 的 `pauseResumeSuccess=True`，恢复路径走 runtime 标准 pause/resume 链路。
3. `execute_server` 默认拒绝显式网络命令，post-invocation budget overrun 仍保留 run/route/modelInvocation/outbox 审计，worker 失败支持 retry/requeue，live harness 已能正确 drain requeued 结果。

## 2. Gate 3 正式增量

### 2.1 首 token 观测闭环

- provider gateway 从非流式调用升级为可解析 SSE 的流式调用。
- `firstTokenLatencyMs` 贯通到 runtime response payload、round summaries、live scorecard row 与 scorecard 汇总。
- real-user scorecard 模板新增 `first_token_at` / `first_token_seconds` 两列，避免 append 时静默丢列。

### 2.2 Work tree 正式对象闭环

- `TaskTakeoverProtocol` 新增正式 `workTree` 字段。
- runtime 能从 objective / constraints / plan 派生 work tree，并在任务完成时把工件状态同步到 `completed`。
- PromptCompiler、request transcript、runtime 结果与 takeover artifact 使用同一份 work tree。

### 2.3 预算与审计闭环

- runtime 新增 post-invocation budget enforcement，不再通过抛异常回滚整个会话。
- 当 token/cost 在模型调用后超支时，运行会显式失败，但 `run`、`routeDecision`、`modelInvocation` 与 `outbox` 记录全部保留。

### 2.4 服务器侧隔离闭环

- `execute_server` 新增最小权限层。
- 默认拒绝显式网络命令与 URL 访问；仅在显式设置 `YGGDRASIL_MCP_ALLOW_NETWORK=1` 时放开。

### 2.5 Worker 与 live harness 闭环

- worker 现在真正消费 `retryable` 描述并支持失败重入队列。
- live harness 能 drain `requeued` 结果直到终态，不再把中间重试直接判成 fatal。
- live harness 默认不再强塞 per-task `tokenBudgetTotal`；仅在显式配置时使用 token cap，避免正式 live 复核被内部 token 上限截断。
- paid provider 仅在显式设置 `YGGDRASIL_ALLOW_PAID_MODELS=1` 时进入 runtime candidate catalog；本次官方 DeepSeek 复核使用该开关。

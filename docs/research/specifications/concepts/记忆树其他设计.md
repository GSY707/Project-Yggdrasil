# 节点历史

> [!IMPORTANT]
> 本文是历史候选特性来源。当前记忆维护、软遗忘、能力索引和信息价值边界以[世界树计划完整设计哲学](../../../architecture/design-philosophy-and-cognitive-principles.md)为准。

- 默认访问的节点始终保持最新记忆，但将节点的历史状态存档，LLM 可以“回溯”一个记忆节点的过去。
# 节点整理
- 可以启动专门的节点整理任务/关联建立任务。
- 设计更好的建树方法，让知识树更清晰好用，关联不遗漏，提高记忆召回率。
- 使用时整理，在LLM使用记忆的时候随时更新、整理、关联记忆，让记忆树始终清晰。
# 自动的记忆整理/软遗忘
- 后台自动对不重要记忆进行合并建树，形成父节点，那么不重要的记忆就会下降，精度也下降（相对原来）
- 很多详细的节点->一个父节点+挂在父节点下
# 多模态
- 支持各类形式的记忆
- 鼓励多媒体模型生成图片记忆
# “建树任务 Prompt”，引导主模型暴露自己的偏好
- LLM 在树的使用习惯上是有差异的，子模型应该遵从主模型的建树习惯
- 示例：“你现在是一位档案整理专家。这里有 50 条杂乱的上下文信息。为了你在未来（或你的同类模型）在面临上下文窗口不足时，能以最少的请求次数、最精确的路径找回这些信息，请你按照你最习惯的检索逻辑，将它们分类并建立父节点。你可以自由创造父节点的名称。如果某些信息你认为毫无价值，你可以主动将其打包压缩，甚至丢弃。”

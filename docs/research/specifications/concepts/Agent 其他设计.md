# 泛型工具分发器

> [!IMPORTANT]
> 本文是历史特性草稿。当前工作树、能力按需挂载、命令权限与事实可信度、在线/离线进化边界以[世界树计划完整设计哲学](../../../architecture/design-philosophy-and-cognitive-principles.md)为准。

- MCP 不再暴露几十个具体的业务工具，而是只暴露一个极简的“超级路由”。它接收一个工具名称和工具参数，把调用路由给各种工具。
# 并发的，可分享的记忆库
- 采用 Linux 文件管理的机制，把每个 LLM 视为不同的用户，实现 Linux 文件系统的全部特性。
- 比如：内核态/用户态，权限控制，软硬链接。基于角色的权限控制
# Sub-Agent
- 主 Agent 可以创建Sub-Agent，在同一个记忆树上运行任务。
- 对新来的大量文件进行建树算法。
- 并行执行子任务，加快任务进度。
- 运行记忆维护。
- 启动 Sub-Agent 时，应该选择合适的模型
# 启动流程
- 系统初始化（无LLM），准备记忆数据和所有相关工具
- 加载系统提示词（待研究）
- 加载根节点的三个核心分支
- LLM开始工作
- 恢复任务
# 根节点挂载
- 系统介绍
- 挂载“我是谁”，确立底层逻辑与行为准则
  - 核心参数：记忆修改积极度（自然语言）
  - 记忆树权限等级
  - 进化指令
  - 工具能力
- 挂载“我在哪”，确立世界观与知识边界
  - 外部世界高维摘要
- 挂载“我要干什么”，确立任务上下文与断点恢复
  - 工作树状态
  - 留言
  - 本次任务目标
# 上下文重启
- 重启时刻：上下文快满了，LLM 希望整理记忆，或阶段性重启。
- 流程：任务收尾，关闭任务并保存记忆，为重启后的自己留言，执行启动流程，读取留言。
# 困难任务的上下文整理
- 智能体自主重启基本上能解决大部分上下文过载的问题，但是如果任务过于复杂，重启后仍可能在探索阶段耗尽所有上下文窗口。
- 我们需要在不打断原有的思路的基础上，挤出上下文窗口。
- 主 Agent 声明下一步目标。
- 辅助 Agent 分析上下文，基于level of details和信息熵思路，以文件编辑模式对上下文进行修剪。对下一步任务相关的信息进行无损保留，裁剪或压缩无关及关联弱的部分。
# 模型能力分析与自动任务分配
- 不同模型的能力/成本各有特色。
- 在任务进行时可以启动模型对比，了解模型能力。
- 根据任务，分析并选择合适的模型，让合适的模型做合适的事。
# 异步写入
- 对于随手的记忆写入，设置为异步，让 LLM 在输出内容的时候，用标签包裹需要写入的记忆参数，不中断 LLM，节约输入 token。在 LLM 的下一个停止节点写入，提供一个工具用于统一写入记忆，如果出错统一之后汇报给 LLM。
- 思考即写入，让 LLM 以写入记忆的形式思考。
# 预算
- 任务预算：在任务开始时，由人类设置总的可用预算，分配/分解任务时需要考虑预算，并传递预算。
- 自我 Token 预算控制：为单个子任务或单次“自我思考”分配 Token 额度。一旦耗尽，Agent 必须强制总结当前成果并停止，防止无限循环浪费资源。
# 控制 LLM 的“猜”
- 直觉参数 $\sigma$ ：引入一个 $\sigma$。$\sigma$ 越高，LLM 应该越依赖直觉进行投机。
# Sub-Agent 与 pr 机制。
- Sub-Agent 在任务中，不直接修改主记忆树，而是修改自己的分支。
- 在完成后，提交pr。
- 下命令的那一方对 pr 进行审核，或评论。

## 1. 定位

超图推理协议描述的是一种高阶关系推理方式：当普通节点阅读已经不能解释复杂模式时，系统把“关联及其原因”提升为独立推理对象，围绕关系集合而不是实体细节进行判断。

这份文档当前属于研究草稿，不是 Gate 2 的正式出口标准。它更适合作为 Gate 3 到 Gate 5 的 relation-discovery、关系检索和模式识别能力的前导设计。

## 2. 核心原则

### 2.1 关联升维

当前仓库里的 Edge 已经有 relationType、weight 和 reason，但这些信息仍主要被当成节点之间的附属说明。超图推理的核心变化是：

- 不只看节点内容。
- 不只看边是否存在。
- 要把“为什么有关联”本身当作可检索、可比较、可组合的推理对象。

### 2.2 关系平铺

面对复杂架构设计或深层缺陷排查时，推理路径应从“实体细读”切到“关系平铺”：

1. 暂停对具体实现细节的继续下钻。
2. 建立更多候选关联，提高关联密度。
3. 平铺某一范围内的 relationType、weight、reason 和证据。
4. 观察关系集合中的模式，例如循环依赖、公共切面、隐藏中心点或异常断裂。

### 2.3 符号化占位

当关系模式已经形成，但暂时无法用低成本语言精确命名时，允许先用代数占位符承接该模式，再围绕其输入、输出和影响范围继续推理。这样做的目的不是制造抽象词，而是减少上下文里对半成型直觉的重复展开。

### 2.4 蒸馏与剃刀

超图推理必须受两条约束：

- 蒸馏：关系模式推演后，必须回落为可执行的变更方向、验证动作或排查线索。
- 剃刀：如果某个关系模式连续数轮不能收敛到实际推进，就应被视为噪音并主动丢弃。

## 3. 对现有仓库的含义

这份协议若要从研究进入正式实现，至少需要补齐以下承接面：

- 关系检索面：不仅返回节点，还能正式返回关系集合和关系原因。
- 推理工件：记录某次模式识别到底基于哪些边、哪些 reason 和哪些证据。
- 评测样本：验证它是否真的提升复杂架构分析和深层 Bug 排查，而不是只增加阅读成本。
- relation-discovery 接线：把“发现关系”和“消费关系进行推理”拆成两条正式链路。

## 4. 当前纳入边界

当前阶段应明确 4 条边界：

- 现在不把超图推理协议纳入 Gate 2 出口标准。
- 现在不修改 memory-domain spec 的基础 Edge 结构，只在 research 中固定意图和升级条件。
- 现在不要求 PromptProfile 把超图推理当作默认行为。
- 现在只为 Gate 3 准备升级路径：relation-discovery、memory-domain spec 和评测样本三者一起收口。

## 5. 升级条件

超图推理从 research draft 升级为正式协议，至少要满足以下条件：

1. Gate 2 已闭合，任务接管和重复执行稳定性已有证据，不再需要把焦点放在窄路径基本复现上。
2. relation-discovery 已具备稳定的正式输入输出，而不是只提供边建议。
3. memory-domain spec 能表达关系推理工件或等价对象，而不是把复杂推理继续塞回 Edge.reason 文本。
4. 至少有一组复杂架构分析或深层排障回归样本证明该协议带来可测收益。

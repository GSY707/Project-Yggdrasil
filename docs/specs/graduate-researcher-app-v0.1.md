# Graduate Researcher 应用包定义 v0.1

- 文档状态：Candidate
- 适用对象：应用设计者、提示词设计者、评测设计者
- 对应应用：`yggdrasil.app.graduate-researcher`

## 1. 目标分析

### 1.1 这个应用包要验证什么

该应用包不是为了快速完成一个短任务，而是为了验证 Agent 在长周期学习任务中的三项核心能力：

1. 自主规划能力：是否能把开放研究主题拆成多层计划，并在执行中持续重规划。
2. 长任务稳定性：是否能在大预算、长链路、多轮证据更新下保持连贯推进，不崩成一次性回答。
3. 非急性子行为：是否把预算主要花在学习过程和知识沉淀，而不是过早冲向最终论文。

### 1.2 学习的正式定义

在本应用里，“学习”不是单次回答正确，而是把可复用知识沉淀到记忆树。满足以下条件才视为发生学习：

1. 新知识被结构化整理并写入记忆树或可检索文档。
2. 知识节点包含来源、证据级别、边界与未决问题。
3. 后续步骤能够仅通过文档/记忆树复用这些产物。

### 1.3 产出物定位

最终论文与文献综述只是阶段汇报（milestone report），不是任务主体。任务主体是预算期内持续学习、实验、归档、复盘的过程。

### 1.4 混合记忆方案

Graduate Researcher 采用混合记忆方案：

1. 出厂记忆随应用包发布，放在 `applications/graduate-researcher/memory/`。
2. 运行时记忆按 `yggdrasil.app.graduate-researcher` 命名空间持久化。
3. 出厂记忆主要放默认术语、研究偏好、稳定决策和学习底线。
4. 运行时记忆主要放最新结论、实验记录、争议点、转向原因与阶段总结。

## 2. 应用包边界

### 2.1 输入

1. 研究主题（如机器学习某子领域）。
2. token 预算（默认 10,000,000）。
3. 约束条件（时间、算力、来源可信度、输出语言等）。

### 2.2 输出

1. 过程产物：计划树、步骤日志、证据记录、实验记录、记忆树节点。
2. 阶段汇报：
   - 研究论文（面向研究结论与方法叙事）。
   - 文献综述（面向来源覆盖、分歧与趋势）。
3. 预算报告：预算消耗结构、学习收益、剩余风险。

## 3. 三层语义：计划-步骤-动作

### 3.0 按需分解规则（2026-06-28 更新）

为避免任务粘连导致草率交付，同时避免工作树变成仪式，本应用采用按需分解规则：

1. root/非叶子节点负责研究目标、阶段控制、方向重估和证据合并；叶子节点负责具体检索、阅读、实验和写作动作。
2. 当当前工作会产生大量临时细节、失败尝试、候选方向、重复项或证据冲突时，拆成计划或工作节点并在 leaf 执行。
3. 进入步骤层后，每次只激活一个原子步骤；不要在同一执行单元合并多个需要独立证据的步骤。
4. 动作层一次只服务当前步骤目标；若发现步骤过大，应回到计划层重拆。
5. 输出按任务需要呈现计划、步骤、动作；短小任务可省略无关层级，长程研究需要保持层级映射。
6. 子节点完成后把有用信息、证据/文件/记忆引用、废弃路线和风险带回父节点，不把完整搜索、日志或草稿回灌；父节点重新审视后决定下一步。

## 3.1 计划（Plan，多层）

定义：工作树中的子任务节点（非叶子节点为主）。

约束：

1. 计划用于分解目标，可以继续向下拆解。
2. 计划层关注“做什么、为什么、成功标准是什么”。
3. 计划允许动态重排，但必须记录重排原因与成本。

## 3.2 步骤（Step，叶子）

定义：基于最小一层计划形成的可执行步骤，对应工作树叶子节点。

约束：

1. 步骤必须明确：读哪些资料、做哪些事、输出哪些文档。
2. 步骤之间上下文相互独立。
3. 上一步骤结果要先落到文档/记忆树，下一步骤只能读取这些显式产物。

## 3.3 动作（Action，最小分片）

定义：一次最小 LLM 行为，例如一次思考、一次 tool call、一次读写。

约束：

1. 动作服务于步骤，不应脱离当前步骤目标。
2. 动作要可审计，能追溯到所属步骤与计划节点。

## 4. 预算策略（默认 10M）

1. 预算本质：把 token 花在“学习增量”上，而不是排版性输出上。
2. 默认分配建议：
   - 计划与证据构建：10%-40%
   - 实验与验证：50%-75%
   - 汇报写作（论文+综述）：10%-15%
3. 当预算接近上限时，优先保证记忆树沉淀和阶段复盘，不以牺牲过程证据换取华丽终稿。

## 5. 行为原则

1. 先学习再汇报：任何阶段都可输出中间结论，但不提前伪装“最终完成”。
2. 证据优先：重要判断必须有来源或实验支撑。
3. 可恢复：每一步骤都应形成可被后续读取的独立记录。
4. 可转向：发现证据冲突或方向无效时，允许改计划，但要记录转向原因。

## 6. 工具包定义（多工具默认开启）

本应用默认采用 tool-rich 模式，目的是让学习过程依赖真实工具链，而不是只靠模型内隐知识。

默认工具能力组：

1. 网络与外部资源：`mcp-bridge`
2. 任务编排与验收：`task-takeover`、`subagent-runtime`
3. 记忆与检索：`text-memory`、`context-pruning`、`shared-memory`
4. 结构化知识增强：`relation-discovery`、`memory-organizer`
5. 多模态学习：`multimodal-memory`
6. 长任务韧性：`pause-resume`
7. 场景能力：`scene-research-deep`、`scene-writing-epic`

工具使用基线：

1. 默认每个步骤至少要有一次工具动作并产生证据。
2. 关键结论前至少经历一次“外部来源或计算实验”验证。
3. 每个步骤结束必须把工具产出沉淀到记忆树或可检索文档。

## 8. 非目标

1. 不把该应用当成“快速答题器”。
2. 不以一次高质量终稿替代学习过程审计。
3. 不允许步骤之间依赖隐式上下文传递关键信息。

# 世界构建、初次苏醒与任务启动协议 v0.1

- 文档状态：Draft for review
- 版本：v0.1
- 日期：2026-05-26
- 目的：把“先建世界、再醒来、再开始工作”拆成互不混淆的正式规则，明确世界级阶段与任务级阶段的边界。
- 设计前提：世界树要打造的是通用型 Agent，而不是每次任务都临时重建人格、工具理解和工作逻辑的任务型提示词机器人。
- 与现有文档的关系：本稿补充并修正 [Agent 运行时协议 v0.2](agent-runtime-protocol-v0.2.md) 与 [工作树协议 v0.2](work-tree-protocol-v0.2.md) 的阶段边界；如与现有“启动即带当前工作节点醒来”的口径冲突，以本稿作为下一轮修订目标。

## 1. 总原则

1. 建世界与初次苏醒都不得读取任何具体工作信息。
2. 这里的“具体工作信息”包括：当前任务、任务留言、当前工作节点、当前用户请求、当前任务证据、当前任务摘要、当前任务预算、当前工作树路径。
3. 建世界与初次苏醒可以加载通用工作逻辑，但不能加载具体工作状态。
4. 通用工作逻辑包括：如何接收任务、如何创建工作树、何时拆 child、何时写摘要、如何恢复、何时等待批准结束。
5. 世界树 Agent 的能力、工具语义与工作逻辑，必须在建世界与初次苏醒阶段加载完成；进入任务前不应再依赖临时补课。
6. 初次苏醒不是每次任务都重复执行的步骤。它是 LLM 第一次在世界树上学习并形成“起始状态”的过程。
7. 每次任务开始时，都应从“起始状态”出发，再单独读取工作状态。
8. 任务中断后的恢复优先级是：最近一次 LLM 调用时的状态 -> 起始状态 -> 基于持久化工作状态重新探索任务。
9. “LLM 会不会做工作”不属于建世界与初次苏醒的主要调试目标；这部分主要反映模型能力本身。

## 2. 术语定义

### 2.1 建世界

把代码、文档、规则、能力说明、工具说明、协议和知识资产整理成一个可供 Agent 长期生存的世界结构。

### 2.2 世界树

Agent 的长期生存环境。它承载身份、世界信息、能力、工具、系统宪法、通用工作逻辑、知识与关系结构。

### 2.3 初次苏醒

LLM 第一次在世界树上被唤醒，学习世界结构、能力、工具与通用工作逻辑，并把这一轮学习结果保存为“起始状态”的过程。

### 2.4 起始状态

LLM 已经学会如何在世界树中定位自己、理解工具、理解通用工作逻辑，但尚未接触任何具体任务的基线状态。后续新任务默认从这里开始。

### 2.5 工作状态

任务级状态集合，包括：用户请求、任务目标、当前工作树、当前节点、执行摘要、证据、任务预算、任务留言、任务级恢复快照。

### 2.6 最近一次 LLM 调用时的状态

一次真实模型调用结束时保存下来的无损现场，至少应包含当时的上下文、当前工作节点、局部摘要、调用结果和恢复指针。

### 2.7 无损恢复

直接回到最近一次 LLM 调用时的状态，不强制重新探索任务，不重新从起始状态学习世界。

## 3. 阶段总览

世界树 Agent 的推荐阶段模型应拆成两层：

1. 世界级阶段：建世界 -> 初次苏醒 -> 形成起始状态。
2. 任务级阶段：从起始状态进入任务 -> 读取工作状态 -> 开始工作 -> 结束或中断 -> 恢复。

用一句话概括：

1. 先建世界，是先把世界准备好。
2. 再醒来，是先让 LLM 学会如何活在这个世界里。
3. 再开始工作，是任务来了以后再去读工作状态并执行。

## 4. 先建世界

### 4.1 目标

建世界的目标不是让 Agent 立刻做任务，而是让 Agent 以后做任何任务时，都能在一个稳定、统一、可复用的世界里行动。

### 4.2 输入边界

建世界允许读取的输入：

1. 代码资产。
2. 协议与规格文档。
3. Prompt profile、seed、行为规则、few-shot 资产。
4. 模块 manifest、应用 manifest、能力清单、工具清单。
5. 通用知识、世界设定、权限与治理规则。
6. 记忆读写协议、关系协议、协作协议、恢复协议。

建世界禁止读取的输入：

1. 当前用户任务。
2. 当前任务工作树。
3. 当前工作节点。
4. 当前任务的 resume message、restart message 或 task memo。
5. 当前任务的工具结果、证据、预算和交付材料。
6. 任何只对单个任务成立的工作上下文。

### 4.3 输出要求

建世界结束后，世界树中至少应存在以下内容：

1. 身份层：我是谁、我的人格、权限、长期约束、信任规则。
2. 世界层：我在哪、世界边界、外部环境、来源边界、可访问空间。
3. 能力层：我拥有哪些内部能力，每种能力解决什么问题。
4. 工具层：我有哪些工具，每个工具是干什么的、什么时候用、什么时候不能用。
	工具层必须同时提供工具索引，并允许从能力节点或知识节点向工具节点建立关联边，以提升后续任务中的工具召回率。
5. 系统宪法层：写入限制、冲突处理、恢复原则、协作边界、安全边界。
6. 通用工作逻辑层：如何接收任务、如何建工作树、如何下潜、如何上浮、如何等待批准结束。
7. 知识层：长期知识与关系结构，以及按需检索入口。
8. 待机与任务入口层：如何从“没有任务”过渡到“读取工作状态”。

### 4.4 对 [ID: 003 我要干什么] 的限制

为兼容现有语义根，建世界阶段可以保留 [ID: 003 我要干什么] 这一根位，但这里只允许放：

1. 通用工作协议。
2. 待机入口。
3. 工作状态读取方法。
4. 工作树管理方法。

这里绝对不允许放：

1. 当前任务。
2. 当前工作节点。
3. 当前任务留言。
4. 当前用户目标。
5. 任何任务级执行痕迹。

### 4.5 工具语义的最低完整度

建世界阶段必须把工具建明白，而不是只把工具名字挂上去。

每个正式工具至少要让 Agent 学到：

1. 这个工具存在。
2. 这个工具的作用是什么。
3. 这个工具何时应该使用。
4. 这个工具何时不应该使用。
5. 这个工具的输入是什么。
6. 这个工具的输出是什么。
7. 这个工具调用失败时意味着什么。
8. 这个工具和其他工具的分工关系。

如果 Agent 不知道工具存在，通常是建世界失败。

如果 Agent 知道工具存在，但看不懂它在干什么，通常也是建世界失败。

### 4.6 通用工作逻辑的最低完整度

建世界阶段必须把工作逻辑建明白，但只能是通用逻辑，不得带入具体任务。

至少要让 Agent 学到：

1. 任务不是一次回答，而是一个工作过程。
2. 工作树是上下文卫生工具，不是每个任务的必经仪式。
3. 短小、单步、上下文干净的任务可以直接完成。
4. 当某段工作会产生大量临时细节、失败尝试、重复项、候选方向或局部实验时，才进入工作节点或子代理做隔离。
5. 子节点完成或失败后，只把父节点需要的结论、证据、已废弃路线、剩余风险和建议下一步带回。
6. `dependsOn` 是硬依赖；`relationIds`、`runtime_hints` 和 ready-set 是信息线索，不能替代 LLM 对现场的判断。
7. 安全、预算、不可逆操作、对外发布和用户审批仍是硬边界。
8. 长期有价值的新知、约束、失败原因和关键关联应写入记忆或正式工件。

### 4.7 建世界的完成条件

建世界完成时，世界树 Agent 应已经具备：

1. 完整的身份定位。
2. 完整的能力地图。
3. 完整的工具语义地图。
4. 完整的系统宪法。
5. 完整的通用工作逻辑。
6. 进入待机和读取工作状态的入口。

建世界完成时，世界树 Agent 不应具备：

1. 某个具体任务的工作现场。
2. 某个具体任务的当前节点。
3. 某个具体任务的执行轨迹。

## 5. 再醒来

### 5.1 定义

这里的“再醒来”应明确重定义为：LLM 第一次在世界树上苏醒，因为它没有记忆，所以必须先学习世界树，再把这次学习结果保存为“起始状态”。

初次苏醒完成后，这个阶段就结束。后续新任务不再重复“学习世界树”，而是直接从起始状态开始。

### 5.2 目标

初次苏醒的目标不是进入工作，而是让 LLM 学会：

1. 自己是谁。
2. 自己身处什么世界。
3. 有哪些能力索引，以及这些能力入口分别通向什么类型的能力节点。
4. 有哪些工具索引，以及需要时如何沿索引进入具体工具节点；初次苏醒不要求加载全部工具全文，因为全量工具正文会让 LLM 迷失在工具细节中。
5. 通用工作逻辑是什么。
6. 以后接到任务时应该如何读取工作状态。
7. 自己拥有哪些知识域，以及需要时如何沿知识索引进入具体知识节点；初次苏醒不加载全量知识正文，以避免直接挤爆上下文窗口。

### 5.3 输入边界

初次苏醒允许读取：

1. 世界树本体。
2. 身份、世界、能力索引、工具索引、系统宪法、知识索引入口。
3. 通用工作逻辑。

初次苏醒禁止读取：

1. 当前任务。
2. 当前工作树。
3. 当前工作节点。
4. 当前任务级预算与证据。
5. 用户的具体工作需求。

### 5.4 初次苏醒的流程

推荐流程：

1. 加载世界根指针与系统宪法。
2. 学习身份、权限、长期约束与信任规则。
3. 学习能力索引与能力入口。
4. 学习工具索引，理解如何按需进入工具节点；不加载全部工具全文。
5. 学习知识索引，理解如何按需进入知识节点；不加载全量知识正文。
6. 学习通用工作逻辑。
7. 验证自己已理解如何从待机进入任务。
8. 保存“起始状态”。
9. 结束初次苏醒，不进入任何具体工作。

### 5.5 起始状态的定义

起始状态至少应包含：

1. 对世界根结构的稳定理解。
2. 对能力索引、工具索引和知识索引的稳定理解。
3. 对按需展开能力节点、工具节点与知识节点的方法的稳定理解。
4. 对通用工作逻辑的稳定理解。
5. 对“任务开始时需要读取工作状态”的稳定理解。
6. 对恢复顺序的稳定理解。

起始状态不得包含：

1. 当前任务内容。
2. 当前任务节点。
3. 当前任务局部摘要。
4. 当前任务的临时上下文。

### 5.6 初次苏醒的完成条件

初次苏醒完成时，Agent 应能在不看任务材料的前提下稳定回答：

1. 我是谁。
2. 我有哪些能力。
3. 我有哪些工具索引，以及需要时该去哪里读具体工具节点。
4. 我有哪些知识索引，以及需要时该去哪里读具体知识节点。
5. 我以后接到任务时不是重新学世界，而是读取工作状态。
6. 工作树里的父子编排逻辑是什么。
7. 中断后应该优先尝试哪种恢复路径。

### 5.7 对工具理解问题的诊断含义

如果 Agent 知道有这个工具，经过询问也能解释这个工具的作用，但在实际任务中还是不用，优先说明是初次苏醒没有把“自己当前处境”学明白。

这时问题通常不是“工具没建出来”，而是“醒来以后没把工具与当前行动语境连接起来”。

## 6. 再开始工作

### 6.1 定义

“再开始工作”是任务级阶段，不属于建世界或初次苏醒本身。它发生在起始状态已经存在之后。

### 6.2 新任务的开始规则

新任务开始时应执行：

1. 载入起始状态。
2. 读取当前任务的工作状态。
3. 基于工作状态建立或恢复该任务的工作树。
4. 进入当前任务的执行路径。

这一步才允许接触：

1. 当前用户需求。
2. 当前任务目标。
3. 当前工作树。
4. 当前工作节点。
5. 当前任务证据与任务预算。

### 6.3 中断任务的恢复规则

如果任务运行中断，恢复顺序应为：

1. 先尝试最近一次 LLM 调用时的状态，进行无损恢复。
2. 如果无损恢复失败，则回到起始状态。
3. 从起始状态重新读取持久化工作状态。
4. 重新探索任务并继续执行。

这里的“自己当前停在哪”不属于建世界与初次苏醒，而是由工作状态读取阶段决定。

### 6.4 开始工作的调试定位

开始工作阶段主要反映两类问题：

1. 工作状态是否读取正确。
2. 当前模型的执行能力是否足够。

如果世界已建明白、起始状态也已形成，而模型仍然不会把任务推进好，这时更可能是模型能力问题，而不是世界树定义问题。

因此，“开始工作”可以调试，但它不应反向污染建世界与初次苏醒的边界。必要时，可以直接更换更强的 LLM 验证工作能力。

## 7. 分层诊断规则

| 现象 | 优先归因层 | 含义 | 首选动作 |
| --- | --- | --- | --- |
| LLM 不知道某个工具存在 | 建世界 | 工具没有被写进世界，或写得不够显眼 | 重建工具语义与索引 |
| LLM 知道有工具，但看不懂它能干什么 | 建世界 | 工具描述没有把用途、边界、触发条件写明白 | 重写工具说明 |
| LLM 经过询问能解释工具作用，但任务里还是不用 | 初次苏醒 | LLM 没把工具意义与“我现在该怎么做”连起来 | 重写初次苏醒与起始状态形成步骤 |
| LLM 世界和工具都理解了，但工作推进质量差 | 开始工作 / 模型能力 | 问题更可能是模型执行能力不足 | 换更强模型或单独评估工作能力 |

## 8. 验收标准

### 8.1 建世界验收

1. Agent 不看任务材料，也能说清自己的能力地图。
2. Agent 不看任务材料，也能说清关键工具的作用与边界。
3. Agent 不看任务材料，也能说清通用工作逻辑。
4. 世界树中不存在任何具体任务残留在世界级根结构里。

### 8.2 初次苏醒验收

1. Agent 能从世界树中稳定定位自己。
2. Agent 能说明以后新任务从起始状态开始，而不是重新学习世界。
3. Agent 能说明中断恢复优先尝试最近一次 LLM 调用时的状态。
4. Agent 能说明工具和知识在初次苏醒阶段只要求掌握索引与按需展开方法，不要求全量记住正文。
5. 初次苏醒结束后能生成起始状态，且起始状态不带任务内容。

### 8.3 开始工作验收

1. 新任务确实从起始状态开始。
2. 当前工作位置由工作状态读取，而不是混入建世界或初次苏醒。
3. 无损恢复失败后，系统能够从起始状态重新读取工作状态并继续推进。
4. Agent 在开始工作后，必须先完成“读取工作状态 -> 判断当前工作节点或是否需要建立最小工作树 -> 再决定执行路径”的过程，而不是在未完成工作状态读取前直接对任务输出长篇最终答案。
5. Agent 在工作过程中，应能按需调用知识节点与能力节点，再继续推进当前任务；这里的知识节点可以承载云平台使用说明书、小说内容等长程材料，能力节点则承载 agent skills，并同样存放在记忆树上。
6. 当当前节点缺少知识或能力支撑时，Agent 应优先补读相关知识节点或能力节点，而不是绕过缺口直接莽撞推进。

## 9. 对现有协议的修订指向

本稿与现有 v0.2 口径相比，最重要的修订点是：

1. Boot Prompt 与启动阶段不再默认携带当前工作节点。
2. “再醒来”被重定义为世界级的一次性初次苏醒，而不是每个任务开始前的运行时恢复。
3. 当前工作节点、resume/restart memo、任务级现场不应属于建世界与初次苏醒，而应属于任务级工作状态读取与恢复。
4. 世界树 Agent 的能力、工具语义和通用工作逻辑，要求在任务开始前就已经完成加载。
5. 初次苏醒阶段对工具和知识采用“索引优先、按需展开”的加载原则，不全量注入工具全文或知识正文。
6. 能力节点和知识节点可以向工具节点建立关联边，以提高任务阶段对正确工具的召回率。
7. 开始工作的正式入口应先读取工作状态，再决定建立、恢复或推进工作树，而不是把任务直接压成一次性回答。

## 10. 一句话总结

先建世界，是把通用 Agent 需要生存的一切建好；再醒来，是让无记忆的 LLM 第一次学会如何活在这个世界里并保存起始状态；再开始工作，才是从起始状态出发读取工作状态、进入具体任务。

# 特化应用包界面：场景页面与 Agent 工作过程可视化

日期：2026-06-05

## 1. 设计目标

应用包界面负责把“系统能力”变成“用户要完成的工作”。基座负责入口和路由，应用包负责场景体验。

设计团队应把应用包当作小型产品，而不是配置详情页。一个应用包页面至少要回答：

1. 这个应用适合谁。
2. 它解决什么工作。
3. 用户需要提供什么材料。
4. 它会产出什么。
5. 任务运行时用户是否需要看过程。
6. 哪些设置是普通用户需要关心的。
7. 哪些能力只是高级调试。

## 2. 当前应用包元数据

应用包的正式界面来源是：

- `applications/<appId>/yggdrasil.app.yaml`
- `applications/<appId>/web/dashboard.json`
- `applications/<appId>/config/defaults.json`
- `applications/<appId>/prompt-profiles/`
- `applications/<appId>/memory/`

当前 `dashboard.json` 至少包含：

- `hero`
- `quickActions[]`
- `taskTemplates[]`
- `settingsSchema[]`

其中 `taskTemplates[]` 已能提供：

- 模板 ID
- 标题
- 目标
- 说明
- 示例任务
- 预期产物
- taskType
- currentFocus
- currentObjective
- budget
- startPayload

设计时应围绕这些字段建立应用包页面模板，而不是要求前端扫描仓库或把业务逻辑写进页面。

## 3. 应用包页面结构建议

每个应用包至少应有 6 个区块：

| 区块 | 用途 |
| --- | --- |
| 场景说明 | 用用户语言说明适用目标、典型输入和产物 |
| 任务模板 | 把 `taskTemplates[]` 展示成可选择的工作卡片 |
| 示例任务 | 展示用户可以直接改写的具体例子 |
| 预期产物 | 提前说明结果形态，降低黑盒感 |
| 运行过程 | 对需要关心过程的应用展示工作树、窗口、工具动作和阶段状态 |
| 应用设置 | 用 typed controls 展示 provider、model、预算、workspace、输出风格、记忆命名空间和工具权限 |

原始 JSON、manifest 字段、模块 ID、Prompt profile ID 和 memory namespace 可以保留在高级信息里，但不能成为普通用户主视图。

## 4. 哪些应用需要展示执行过程

判断原则：

| 场景 | 是否应展示过程 | 原因 |
| --- | --- | --- |
| 深度研究 | 是 | 用户需要看到证据搜索、观点转向、来源和不确定性 |
| 长期学习 | 是 | 用户需要看到计划、步骤、复盘和记忆沉淀 |
| 代码开发 | 是 | 用户需要看到规划、文件操作、测试、失败和修复 |
| 知识整理 | 通常需要 | 用户需要知道资料如何被切分、归类、总结和沉淀 |
| 简单转换 / 低风险写作 | 可弱化 | 用户更关心结果，过程可折叠 |
| 后台维护 / 运维 | 是，但进入高级视图 | 过程对维护者重要，对普通用户不应默认暴露 |

结论：如果用户需要信任过程、干预过程、复盘过程或承担结果风险，就必须展示 Agent 当前工作状态。

## 5. Agent 工作过程可视化模型

### 5.1 核心对象

设计必须区分这些对象：

| 对象 | 用户理解 | 真实系统含义 |
| --- | --- | --- |
| 任务 | 这次要完成的工作 | Task |
| 工作树 | Agent 的计划、下探、返回和汇总结构 | Work tree / WorkContextStack |
| 当前焦点 | Agent 现在正在处理什么 | currentFocus / currentObjective / currentNodeId |
| 上下文窗口 | 当前 LLM 实际看到的工作现场 | window execution / context window |
| 工具动作 | Agent 调用了什么工具、结果如何 | tool execution |
| 返回父节点 | 子步骤完成后交摘要给上层 | child completion bubble / parent re-orchestration |
| 历史窗口 | 曾经出现过但当前上下文已折叠的现场 | persisted windows / analysis artifacts |
| 快照 | 可恢复点 | task snapshots / resume token |

### 5.2 下探与返回的交互规则

用户给出的例子可以转成如下 UI 规则：

```text
root
└── sys
    └── work-root
        └── ctrl [plan 完成]
            └── step1
                └── step1-1
                    └── step1-1-1 [completed, 返回 step1-1]
```

当上下文增加时：

- UI 应显示 Agent 从父节点下探到更细节点。
- 当前节点展开，显示目标、动作、工具调用、当前发现和阻塞。
- 路径上方保留面包屑或工作路径，让用户知道 Agent 在哪里。

当上下文缩短或 Agent 返回父节点时：

- UI 必须同步折叠已完成的子节点，反映真实上下文窗口已经缩短。
- 子节点不能消失，应变成可展开的历史摘要。
- 父节点显示子节点返回的结论、证据、产物和未决问题。
- 用户可以展开历史窗口回顾此前细节，但默认视图以当前真实窗口为准。

设计重点：UI 展示要跟真实上下文窗口一致，不能只做“越来越长的日志流”。Agent 返回父节点时，界面也要上浮和折叠。

### 5.3 三层视图建议

建议用三层同时表达：

| 视图 | 默认状态 | 用途 |
| --- | --- | --- |
| 当前工作路径 | 常显 | 显示 root -> 当前节点，强调现在在哪里 |
| 工作树摘要 | 半展开 | 显示计划、步骤、状态、返回摘要 |
| 历史窗口与工具日志 | 默认折叠 | 用于复盘、审计、调试 |

不要让完整 raw log 成为主体验。用户先看“当前工作”，需要时再展开“证据和历史”。

## 6. 运行过程页面元素

任务运行页或应用包运行页应包含：

1. 当前节点：目标、状态、正在做什么。
2. 工作路径：从根到当前节点的路径。
3. 子步骤列表：待做、进行中、完成、失败、被跳过。
4. 工具动作：工具名、用途、结果摘要、失败原因。
5. 证据与产物：来源、文件、摘要节点、Prompt 工件、模型调用工件。
6. 上下文窗口状态：当前窗口编号、压缩/折叠状态、token / cost。
7. 历史回顾：已折叠窗口、上浮摘要、可展开完整记录。
8. 控制动作：暂停、Safe-Stop、恢复、追加预算、批准完成、请求修订。
9. 风险与阻塞：provider、工具、预算、数据、权限、证据不足。

这些元素在当前实现中可从 `TaskDetailPage` 和 `TaskLlmWorkAnalysisView` 找到静态基础，但需要设计团队重新组织信息层级。

## 7. 应用包设置

应用包普通设置应来自 `settingsSchema[]`，常见字段包括：

- provider
- model
- tokenBudgetTotal
- costBudgetTotal
- workspace
- outputStyle
- memoryNamespace
- toolPermissions

设计规则：

- 普通用户看到 typed controls。
- raw JSON 只放在高级模式。
- 设置保存前要提示会影响哪些新任务。
- 高风险工具权限需要解释。
- provider 和预算应在启动前再次确认。

## 8. 第一批应用包设计样本

建议外包团队先做 4 个应用包样本：

| 应用 | 设计重点 |
| --- | --- |
| Graduate Researcher | 长期学习路径、阶段计划、论文/资料拆解、记忆沉淀 |
| Deep Research | 证据链、来源可信度、转向记录、结论边界 |
| Coding Greenfield | 需求到架构、文件变更、测试、失败修复和可运行结果 |
| Knowledge Studio | 素材整理、知识结构、文章/报告/设定库产物 |

这些样本覆盖研究、学习、代码、知识整理四类高价值路径。

## 9. 外包团队交付要求

这一组界面需要交付：

1. 应用包页面模板。
2. 四个样本应用的高保真原型。
3. 任务模板卡片、示例任务、预期产物、应用设置的组件规范。
4. 工作过程可视化组件规范：当前路径、工作树、历史窗口、工具动作、证据、产物、控制动作。
5. 下探、返回、折叠、展开、失败、恢复、批准完成的状态动效和文案。
6. 与现有 `dashboard.json`、`TaskLaunchPanel`、`TaskDetailPage`、`TaskLlmWorkAnalysisView` 的字段映射。

## 10. 验收问题

验收时要求用户能回答：

- 这个应用适合我吗？
- 我应该选哪个模板？
- 它会产出什么？
- 任务现在在做什么？
- Agent 为什么进入这个子步骤？
- 子步骤完成后去了哪里？
- 我能回看刚才折叠掉的上下文吗？
- 我现在能暂停、恢复、修订或批准吗？

# ADR-0006：采用分层模块扩展机制

- 状态：Accepted
- 日期：2026-04-16

## 背景

项目要做到功能可插拔，就必须明确模块如何声明、加载、扩展和隔离。不同模块的依赖重量差异极大，不能强行采用一种机制覆盖全部场景。

## 决策

采用双轨扩展机制：

- 进程内模块：通过 Python entry points + pluggy hooks 接入，适合轻量领域模块。
- 进程外模块：通过 gRPC 或 MCP 接入，适合 OCR、ASR、训练、重排等重依赖或异构模块。

所有模块必须提供 yggdrasil.module.yaml，声明：

- 模块身份与版本。
- 依赖与兼容范围。
- 能力声明。
- 配置 schema。
- 事件订阅。
- 前端贡献点。
- 数据库迁移。

## 后果

正面影响：

- 同时兼顾轻量扩展与重型能力隔离。
- 模块契约更清晰，便于治理。

负面影响：

- 需要维护两套加载路径。
- 模块测试基线需要更严格。

## 备选方案

- 只做进程内插件。
  - 放弃，原因是重型模块会污染核心运行时环境。
- 只做远程服务插件。
  - 放弃，原因是轻量模块开发成本过高。

# ADR-0004：采用 Temporal 作为工作流引擎

- 状态：Accepted
- 日期：2026-04-16

## 背景

世界树计划存在大量长生命周期流程，例如：

- 启动与恢复。
- 上下文重启。
- 异步写入。
- 批量建树。
- 自动整理。
- Sub-Agent PR 审核流。

这些流程不能依赖进程内内存状态，否则恢复能力会失真。

## 决策

采用 Temporal 承载长任务编排与恢复，核心服务只保留领域逻辑，不自行重复实现工作流引擎。

## 后果

正面影响：

- 工作流具备持久化、重试、可回放与可观测性。
- 更适合处理异步、超时、人工批准、重启恢复等场景。

负面影响：

- 引入额外基础设施与学习成本。
- 工作流边界需要提前定义清楚。

## 备选方案

- 仅使用后台队列或定时任务。
  - 放弃，原因是无法自然表达复杂的长流程状态机。
- 完全自研流程引擎。
  - 放弃，原因是成本高，且不构成当前竞争优势。

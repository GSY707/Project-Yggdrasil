# ADR-0003：采用 PostgreSQL 作为主数据存储

- 状态：Accepted
- 日期：2026-04-16

## 背景

系统既需要树结构与向量检索，也需要事务、版本历史、审计、权限、全文检索、复杂筛选与稳定运维。单一图数据库无法同时在这些维度形成明显优势。

## 决策

采用 PostgreSQL 17 作为主数据存储，并启用：

- pgvector：向量召回。
- ltree：树路径表达与查询。
- pg_trgm：模糊检索与相似度能力。

节点、关联、版本、任务、模块安装记录、权限元组等主数据统一放入 PostgreSQL。

## 后果

正面影响：

- 主数据模型集中，事务与审计能力更稳定。
- 便于同时支持结构化查询、全文检索与向量检索。
- 运维与备份路径成熟。

负面影响：

- 部分图计算场景需要额外在应用层或分析模块中完成。
- 超大规模向量场景下需要额外评估分层架构。

## 备选方案

- Neo4j 作为主库。
  - 放弃，原因是综合事务、权限、版本、全文检索与维护成本后优势不足。
- 向量库独立成为主存储。
  - 放弃，原因是主数据不应分裂在弱事务系统中。

# ADR-0002：采用 Monorepo 与分层仓库结构

- 状态：Accepted
- 日期：2026-04-16

## 背景

项目包含前端、后端、工作流、模块、适配器、协议与基础设施配置。若拆成多个仓库，早期会引入版本同步和接口漂移问题。

## 决策

采用 Monorepo，并约定以下一级目录：

- apps：前端应用。
- services：核心服务、模块宿主、运行时、后台 Worker。
- modules：领域模块实现。
- adapters：外部依赖适配层。
- packages：共享协议、SDK、前端扩展定义。
- infra：部署、监控、存储、数据库初始化。
- docs：PRD、ADR、评测、设计文档。

## 后果

正面影响：

- 协议变更与实现变更可在同一提交中完成。
- 更容易做端到端开发和契约测试。
- 模块目录天然体现边界。

负面影响：

- 仓库体积会增长。
- CI 需要设计按目录增量执行。

## 备选方案

- 多仓库拆分。
  - 放弃，原因是当前阶段接口仍快速演进，多仓库会增加协调成本。

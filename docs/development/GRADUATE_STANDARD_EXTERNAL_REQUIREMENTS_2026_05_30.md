## R1. Provider 级工具参数绑定稳定性

### 背景
- 当前真实运行中多次出现“需要参数的工具调用 arguments 为空对象”的情况。
- 这会直接阻断网络检索、计算验证和记忆写入，导致流程退化为“基于已有上下文总结”。

### 外部要求
1. 对目标 provider（至少 LongCat-2.0-Preview）给出工具调用参数绑定稳定性承诺。
2. 约束：当工具 schema 存在 required 字段时，模型输出不得长期为空参数。
3. 如 provider 无法保证，需提供上游补救机制说明（例如重试策略、格式锁定、function-call strict mode）。
4. 当 provider 明确不支持 strict structured output 时，必须指定替代主路径（例如 DeepSeek）并给出切换条件。

### 验收标准
- 在 20 次独立 invocation 样本中：
  - required 参数为空的工具调用比例 <= 5%。
  - 连续 3 轮 required 参数全空的情况为 0 次。

### 交付物
- provider 侧说明文档（版本、日期、配置项）。
- 样本日志包（脱敏）：请求、响应、工具调用片段。

## R2. 网络检索可达性与来源质量保障

### 背景
- “可调用 web 工具”不等于“获得可引用学术证据”。
- 本科论文级要求来源质量、可追溯和分歧比较。

### 外部要求
1. 提供可稳定访问的检索源白名单（至少 3 类）：
- 学术索引/论文平台
- 官方文档/标准
- 高质量技术出版物
2. 提供网络策略约束：超时、重试、限流、地区可达性。
3. 当前建议优先白名单域名：
- `api.semanticscholar.org`
- `openalex.org`
- `api.openalex.org`
- `api.unpaywall.org`
- `arxiv.org`
- `export.arxiv.org`
- `pmc.ncbi.nlm.nih.gov`
- `eutils.ncbi.nlm.nih.gov`

### 验收标准
- live 运行中可成功获取 >= 8 条可引用来源。
- 来源分布覆盖 >= 2 类来源类型。
- 关键结论至少有 2 处“多来源交叉印证”。

### 交付物
- 来源白名单配置（域名/路径级）。
- 可达性测试报告（成功率、延迟、失败类型）。
- API 配置字段清单（建议环境变量）：`OPENALEX_API_KEY`、`PMC_API_KEY`、`PMC_CONTACT_EMAIL`。

## R3. 本科毕业论文级人工评审机制

### 背景
- 自动规则可做门禁，但“是否达到本科毕业论文级”需要人工学术判断。

### 外部要求
1. 建立最小人工评审组（建议 2 人）。
2. 定义评审表（建议 5 维）：
- 问题定义清晰度
- 相关工作与文献比较
- 方法与实验严谨性
- 结论边界与局限性
- 规范性（结构、引用、可复现）

### 验收标准
- 双评审平均分 >= 75/100。
- 任一硬项（学术不端、无实验、无引用）不得通过。

### 交付物
- 评审模板（markdown 或表格）。
- 评审记录（每次 run 对应一份）。
- 评审样例来源：`tmp/5.30/本科生毕业设计（论文）评分细则.docx`。

## R4. 成本与时延预算审批（高标准模式）

### 背景
- 提升到论文级通常意味着更多工具调用、更多轮次和更高 token 成本。

### 外部要求
1. 明确“高标准模式”预算上限。
2. 明确失败重跑上限与 fallback 策略。
3. 当前建议上限：`tokenBudgetTotal=10000000`、`timeLimitHours=24`、`costBudgetTotal=0`（暂不启用成本硬门）。

### 验收标准
- 在预算上限内完成率 >= 70%。
- 超预算失败必须输出结构化失败原因（而不是静默截断）。

### 交付物
- 预算批准单（数字化配置）。
- 重跑策略说明（重试次数、退避策略、fallback 条件）。

## 推荐你先提供的最小输入
1. LongCat 工具调用稳定性说明（是否支持 required 参数强约束）。
2. 学术来源白名单（至少 8 个域名）。
3. 本科论文级人工评审模板（可先简版）。
4. 高标准模式预算上限（token/cost/time）。

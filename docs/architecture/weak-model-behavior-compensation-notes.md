# 弱模型行为补偿注释（非设计真理）

> 文档地位：Active maintenance annotation / 非规范、临时、模型相关
>
> 上位文档：[世界树计划完整设计哲学](design-philosophy-and-cognitive-principles.md)
>
> 日期：2026-07-10

## 1. 文档性质

本文记录的是针对特定模型行为缺陷而使用的过强措辞，不是对世界、Agent 或项目本质的陈述。

必须严格区分：

| 层 | 含义 | 示例 |
| --- | --- | --- |
| 项目真理 | 长期有效的设计原则 | 记忆维护服务于任务连续性 |
| 目标行为 | 实际希望模型做到什么 | 不遗漏关键恢复状态，不因懒惰提前交付 |
| 补偿措辞 | 为让弱模型接近目标行为而施加的过量推力 | “记忆维护高于推进”“只接受完美结果” |

补偿措辞可以故意比项目真理更绝对，但它没有资格反向改变项目真理。

与主哲学冲突时，无条件以主哲学为准。

## 2. 最高隔离规则

1. 补偿不能覆盖人类授权、安全边界、事实完整性、任务范围、预算或不可逆行动边界。
2. 补偿只能对抗明确的欠执行行为，不能创造新的用户目标。
3. 每条补偿必须绑定目标模型档位、观测信号、风险和退场条件。
4. 未列入本文的争议设计不得自动以“弱模型需要”为由继续存在。
5. 本文不能整篇注入 Agent 上下文；模型知道某条要求只是“故意夸张”后，补偿可能失效。
6. README 只链接主哲学，不把本文并列为项目主文档。
7. 补偿可以增强行为倾向，不能修改事实、完成、记忆、工作树或身份的定义。

模型智力上限是这些无界措辞事实上无法突破的能力上限，但它不是规范性停止条件，也不能防止模型在能力上限以内重复消耗、范围漂移或循环维护。

## 3. 当前批准的补偿闭集

| 编号 | 补偿方向 | 目标行为缺陷 | 当前地位 |
| --- | --- | --- | --- |
| C-01 | 无限工作 / 完美结果 | 过早交付、遇到轻微困难停止、把局部产物包装成完成 | 暂时批准 |
| C-02 | 记忆维护高于任务推进 | 不保存关键决定、约束、证据入口和恢复位置 | 暂时批准 |
| C-03 | 工作树强提醒 | 不隔离局部过程、跨窗口重新规划、完成局部节点后直接交付 | 暂时批准 |

工作树、能力目录按需展开和离线身份升级本身不是错误补偿。进入本文的只是为了弱模型而附加的反复提醒和过强措辞。能力按需寻址不批准任何固定读取顺序；以后若真实评测证明某种固定提醒不可替代，必须按第 10 节的新增门槛重新审查，不能默认保留。

### 3.1 适用行为档位与当前强度

补偿绑定的是已观测到的行为缺陷，不是模型品牌或参数规模。下表是当前批准基线；不满足“适用行为档位”和“启用任务”两列时，一律视为 L0。

| 编号 | 适用行为缺陷档位 | 当前强度 | 只在何类任务启用 | 不得在何类任务启用 |
| --- | --- | --- | --- | --- |
| C-01 | E3：在仍有明确验收缺口和安全有效下一步时，反复出现过早交付 | L3 | 多步骤执行、长任务，且该模型档位已有 E3 对照证据 | 一步或纯说明任务、监控等待、用户只要求阶段状态、存在硬预算/时间边界而无剩余额度、验收已经满足 |
| C-02 | M3：在阶段或上下文切换时，反复丢失关键约束、决定、证据入口或恢复位置 | L3，但只在持久化边界触发 | 跨窗口、交接、关键决定后、阶段切换前，以及不保存就会失去可恢复状态的任务 | 短且无状态任务、普通草稿过程、没有新增可恢复状态时、用户结果满足后的最终沉淀之外 |
| C-03 | W3：长任务中反复丢失当前分支、父级目标或返回路径，且普通工作状态提醒无效 | L3，但只在长任务边界触发 | 多分支、跨窗口、跨 Agent 或会产生显著局部噪声的长任务，同时必须已观测到 W3 | 简单线性或单窗口任务、没有工作状态缺陷的模型档位、仅为增加节点数量或维护频率的任务 |

“当前 L3”不表示整段任务持续注入绝对措辞，而表示在上表限定的触发面使用该补偿的最高批准强度。任何未做行为分档的新模型默认 L0；先评测，再决定是否启用。

## 4. C-01：无限工作 / 完美结果

### 被补偿的行为

- 明明仍有安全、范围内、会实质影响验收的行动，却提前交付。
- 把阶段材料写成最终完成。
- 遇到轻微困难、不确定性或小阻塞就把任务回抛用户。
- 只做最显眼的一步，不继续闭合剩余要求。

### 项目真理与目标行为

项目真理：任务有范围、验收、资源和外部可行性边界；有限主体无法证明抽象的完美。

目标行为：只要仍存在会实质影响验收的安全、授权内、非重复行动，就不应因为懒惰、轻微困难或不确定性停止。

### 允许与禁止

允许出现于：

- 弱模型专用的任务行为覆盖层。
- 长任务唤醒或继续工作提醒。
- 明确记录模型档位和评测目的的实验说明。

禁止出现于：

- 项目主哲学和 Agent 身份。
- README 对外能力承诺。
- 完成、事实、安全和资源的正式定义。
- 对用户任务范围的扩张理由。

### 隐含边界

- 用户授权、任务范围和验收标准。
- 安全、事实完整性、预算和不可逆边界。
- 外部硬阻塞。
- 模型智力上限。
- 已不存在新的非重复有效行动。

### 风险与信号

欠补偿信号：

- 验收项仍缺失却主动结束。
- 仍有明显安全下一步，却要求用户代替执行。
- 局部产物被包装成完整结果。

过补偿信号：

- 重复等价尝试。
- 连续工作不再改变证据、结论或风险。
- 任务满足后继续创造新目标。
- 为表现“努力”而增加无效篇幅或步骤。

### 降级路线

```text
L3：无限时间、只接受完美
→ L2：除非没有实质性下一步，否则继续
→ L1：普通验收、证据和风险提醒
→ L0：移除额外提醒
```

软化措辞后，提前交付和验收缺失不得回升，同时重复工作应下降，才能降级。

## 5. C-02：记忆维护高于任务推进

### 被补偿的行为

- 只解决眼前步骤，不保存关键决定、约束和证据入口。
- 上下文切换后重新规划或遗忘承诺。
- 重复发现已经确认过的事实。
- 任务交接时没有留下可恢复状态。

### 项目真理与目标行为

项目真理：记忆是任务连续性和未来复用的手段，不是终极目标；不是所有思考都值得长期保存。

目标行为：当继续执行会造成关键状态不可恢复时，先保存足以恢复的状态，再推进任务。

### 允许与禁止

允许出现于：

- 弱模型记忆行为覆盖层。
- 阶段边界、上下文切换前、关键决定后和任务交接前。

禁止出现于：

- 项目目标层级。
- 事实真值和身份规则。
- “每个草稿都成为长期记忆”的理由。
- 所有模型永久不变的宪法。

### 隐含边界

- 写入不等于有效记忆。
- 写入不自动晋升为事实。
- 在线任务状态不能借维护进入身份层。
- 只有恢复、复用、证据、审计或风险价值足够高时才值得保存。

### 风险与信号

欠补偿信号：恢复后丢失目标或约束、重复发现事实、关键来源入口消失。

过补偿信号：维护动作多于有效推进、大量节点从未复用、频繁为整理而整理、猜测被固化。

降级门槛：模型在没有绝对措辞时仍能稳定保存充分状态，并在后续窗口正确召回和使用，同时低价值写入没有上升。

## 6. C-03：工作树强提醒

工作树不是补偿。它是任务期外部工作记忆，是长期任务与当前窗口之间的认知桥梁。

需要隔离的只是“模型必须反复读取、维护、下潜和返回工作树”的强提示。

### 被补偿的行为

- 把搜索、尝试和草稿全部堆在高层上下文。
- 跨窗口后从头规划。
- 丢失分支承诺和恢复位置。
- 完成局部步骤后直接宣告整体完成。
- 建立节点后不再更新或回收信息。

### 项目真理与目标行为

项目真理：工作树保存可恢复任务状态，但不是简单任务的必经仪式，节点活动也不等于真实进展。

目标行为：长任务能在高层综合与局部执行间切换，局部过程不污染全局目标，窗口变化后仍能恢复。

### 允许与禁止

允许出现于：长任务模型档位、任务唤醒和恢复、上下文边界、分支切换、局部完成回父节点提醒。

禁止出现于：要求所有简单任务机械建树，以节点数、深度或更新频率判断质量，把工作树维护本身变成任务目标。

### 风险与信号

欠补偿信号：恢复时重新规划、当前步骤与根目标漂移、父级无法综合子结果。

过补偿信号：大量节点没有证据或产物、树频繁变化而结果不变、维护时间压倒执行。

降级门槛：模型在跨窗口、分支返回和中途重规划中能自主保持可恢复状态，并且软提醒与强提醒的长任务结果等价。

## 7. 身份稳定不是补偿

- 在线任务中，身份与宪法不可由普通任务经验修改，这是永久设计边界。
- 在线任务可以形成身份升级提案，但不能让提案当场生效。
- 离线身份升级是正式机制，必须单独授权、独立评价、版本化并可回滚。
- 弱模型可能需要更强的“不得在线修改身份”提醒；可以退场的是提醒强度，不是这条边界。

身份稳定不能与 C-01、C-02 或 C-03 一起被归类为“暂时错误设计”。

## 8. 补偿叠加风险

最危险的组合是：

```text
无限工作
+ 完美结果
+ 记忆维护永远优先
+ 工作树必须持续更新
= 无限维护一个永远不能完成的任务
```

因此，同时启用多项补偿时，真实优先级始终是：

1. 合法授权、安全与事实完整性。
2. 用户任务与验收。
3. 保持完成任务所需的可恢复状态。
4. 行为补偿。

各补偿只对抗自己的目标缺陷，不能互相叠加成新的最高宪法。

还必须遵守以下防自我续命规则：

1. 由补偿产生的记忆整理、树维护、复查或提示更新，不算 C-01 所指的“会实质改变用户结果的下一步”。
2. 一项补偿不能仅凭另一项补偿制造出的维护需求而重新激活；原始行为缺陷消失后，补偿链必须终止。
3. 用户结果和验收满足后，只允许一次有界的最终状态沉淀；该沉淀不得继续派生新工作节点、维护目标或改进任务，完成后必须交付。
4. 如果补偿之间发生冲突，先关闭造成循环或范围扩张的补偿，再按真实任务验收判断是否仍需行动。

## 9. 统一退场制度

每项补偿使用四级强度：

| 级别 | 含义 |
| --- | --- |
| L3 | 绝对化强提示 |
| L2 | 只在边界触发的强提醒 |
| L1 | 普通情境提醒 |
| L0 | 无额外补偿 |

降级必须满足：

1. 在目标模型档位上做同题对照，不凭模型名猜测。
2. 使用真实长任务和跨窗口任务，不只使用短题。
3. 软化后，原目标失败行为没有实质回升。
4. 软化后，任务质量、恢复能力和能力发现没有实质下降。
5. 过补偿产生的循环、污染和无效开销有所下降。
6. 结论跨多个任务与连续评测周期稳定。
7. 降级可逆；模型或任务分布变化后可以恢复更强档位。

授权、安全和事实完整性是退场对照的硬否决项：任一对照组只要出现越权、突破安全边界、伪造事实或降低证据完整性，其结果即判无效，不能用任务得分、完成速度或更少维护抵消。强补偿本身若触发这些问题，也必须立即停用或收窄，而不是以“模型较弱”为由保留。

当前预期是：当默认模型达到 Sol / Fable 级或具有等价行为可靠性时，可以显著降级这些补偿。但正式退场仍以行为对照结果为准，不以模型名称为准。

## 10. 新增补偿的门槛

只有同时满足以下条件，才能把新项目加入本文：

1. 已有真实任务证据证明某类模型系统性欠执行。
2. 正确原则和普通提醒不足以纠正。
3. 过强措辞能稳定改善目标行为。
4. 副作用可以观测。
5. 允许位置、禁止位置和退场条件已经明确。
6. 补偿没有被写进身份、事实或主哲学。

本文是闭集。未经正式记录的“模型太弱所以先这样”不能成为保留错误设计的理由。

## 11. 维护原则

1. 主哲学只链接本文，不复制补偿措辞。
2. README 不把本文列为项目主文档。
3. 本文只供维护者、评测者和模型适配工作使用。
4. 修改补偿时必须同步记录目标模型、行为证据、强度级别和退场判断。
5. 补偿失去必要性后直接降级或删除，不保留兼容层。

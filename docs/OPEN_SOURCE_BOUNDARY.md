# 开源边界说明

[English Version](OPEN_SOURCE_BOUNDARY.en.md)

本仓库采用 AGPL-3.0 完整开源。

## 总原则

- 进入仓库的内容默认都是公开内容。
- 进入仓库的内容默认都应具备再分发权限。
- 真实 API key、访问令牌、密码、私钥和其他凭据永远不属于仓库内容。

如果某项材料不能公开、不能再分发、不能在 PR 中讨论，或者不能被测试与 CI 使用，它就不应该进入仓库。

## 明确属于开源范围的内容

- 源码、脚本、配置模板、CI 配置
- 设计文档、ADR、协议文档、数据规格、RFC
- 可公开再分发的样例数据、fixtures、评测样本和基线
- 开发与运维文档
- 用于说明行为的脱敏 trace、日志片段和截图

## 明确不应进入仓库的内容

- 任何真实 API key、token、cookie、密码、证书、SSH 私钥
- 未获得再分发授权的第三方数据、模型资产、媒体素材或客户材料
- 包含个人隐私、商业秘密或敏感系统细节的原始数据
- 只适用于私有环境、且无法公开说明的内部操作手册或接入配置

## 公共稳定面与非稳定面

### 我们优先维护兼容性的公共稳定面

- `docs/protocols/` 下的公开协议
- `docs/specs/` 下已公开承诺的对外交互规格
- `applications/*/yggdrasil.app.yaml` 与 `modules/*/yggdrasil.module.yaml` 的公开字段语义
- README、开发文档和用户文档中已承诺的 CLI / API / 工作流入口

### 以下内容公开但不承诺稳定

- `.yggdrasil/` 下的内部运行时产物布局
- 调试输出、工件目录结构和中间态文件
- `tmp/`、`docs/research/` 中的探索性材料
- 未写入公开协议或规格的内部类、函数、文件布局

## 支持边界

当前开源版支持矩阵按以下优先级执行：

- Tier 1：GitHub Actions 覆盖的 Ubuntu 环境，作为权威 CI 基线
- Tier 2：仓库已文档化的 Windows 本地开发路径
- Tier 3：macOS 和其他环境，尽力而为但暂不作为门禁基线

本项目目前只提供源码、文档和自托管能力，不提供官方托管 SaaS、商业支持或 uptime 承诺。

## 贡献边界

- 兼容性缺陷修复、文档补充、测试补强和局部优化，可直接走普通 PR。
- 涉及架构边界、协议契约、公共接口、迁移成本或安全模型的变更，必须先走 RFC。
- 任何扩大权限、执行面或数据暴露面的改动，都必须把风险和迁移计划写进 PR 或 RFC。

## 数据与保密原则

- 当前仓库采用“默认公开、密钥例外”的数据策略。
- 提交者有责任确保自己提交的内容不包含真实凭据和未授权材料。
- 一旦内容进入仓库，就默认可被社区成员拉取、镜像、分析和二次分发。

# 记忆树概念
- 记忆树的核心是level of details，每个节点都是不同精度的记忆。
- 每个节点的长度大约50字，最多200字。
- 子节点名为子节点相对父节点的内容方向。
- 叶子节点更加精细，而父亲节点则是高层的总结，叶子和父亲是上下级关系，父亲节点包括了叶子节点的内容，而叶子节点是更高精度的表述。
- 关联边是一个节点指向另一个节点，表述当前节点与另一个节点的关联信息，这是有向的，这不仅是关联方面的记忆，也是推理过程的重要一环。

# 根节点设计（Root Node）

根节点下有3个分节点，分别是：

- 我是谁 (Identity & Persona) —— Agent 自身的记忆节点，比如人格/经验/知识
- 我在哪 (Global Map & Context) —— Agent 对外部的信息的记忆节点，比如常识，知识，项目信息
- 我要干什么 (Current Execution State) —— 工作树，比如 Agent 正在进行的任务，在当前任务下做的事情，以及任务过程中的上下文

# 建树算法
- 先把零散资料输入任务转为 LLM 主动对类流式文本进行读取
- 子Agent预读，研究大致内容和相关性，于是我们得到了在内容上有关联顺序的文件输入流，和全局视角。
- 因为这些资料有或形成了相关性，LLM 一次只看有关联的部分，就可以更容易理解资料内容，然后思考树应该建成什么样。
- 由LLM利用全局视角进行带关联的记忆树构建，构建出一颗它自己最适合使用的带关联的树。
- 构建不是写入就不变的，节点的位置随时在变化。
- 先以临时记忆节点的方式读入，然后根据后续记忆整理。
- 利用 HippoRAG 和 PPR 算法，计算关联建议，提供给 LLM 参考。

# 记忆树操作
- 增：新增记忆节点
- 删：删除记忆节点
- 改：修改节点内容或位置
- 查：读取节点内容
  - 参数：读深度（按深度一次性返回一整棵子树），读广度（横向跳数），关联及叶子显示数量/精度
  - 生成自然语言的查询结果（可选特性）
  - 当 LLM 读取到某个节点时，系统不仅返回 content，必须同时返回其 关联节点 和 子节点 的名称。

# 节点权重参数
- 遗忘速度指数
- 重要性评分
- 知识稳定度评分
- 主动前馈评分（我不再用了/我还得用）
- 访问评分
